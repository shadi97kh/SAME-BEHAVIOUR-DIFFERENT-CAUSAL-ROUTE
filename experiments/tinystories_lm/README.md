# Same Behaviour, Different Causal Route: natural-language extension (Appendix R)

Code, logs and analysis for the TinyStories language-model experiments in Appendix R of
*Same Behaviour, Different Causal Route: Post-Convergence Steering in Recurrent–Attention Hybrids*
(ICLR 2027 submission, anonymous).

A from-scratch recurrent–attention language model keeps the paper's identifiable dual-route readout at every
position (one GRU, one retrieval read, additive logits). We screen recurrent viability across context length and
GRU width, then apply the late retrieval price and measure how much of retrieval's function transfers to recurrence.

**Main result:** no tested configuration makes recurrence a viable copying substitute (best copy viability 0.931).
Late pricing (λ = 0.1) transfers a stable fraction of retrieval's perplexity contribution,
*h* = 0.393 ± 0.006 and 0.393 ± 0.025 over three seeds at the lowest and highest viability, at 1–2% perplexity cost.
Retrieval never becomes deletable (0 of 9 priced runs), and a matched post-hoc attenuation control costs 18–38% perplexity.

## 1. Reproduce the tables and figure from the released logs (CPU, under a minute)

```bash
pip install numpy pandas matplotlib
python analyze.py --out results --check
```

This regenerates `results/analysis/` (`screen.csv`, `steering_per_seed.csv`, `steering_summary.csv`,
`tables.tex`, `tinystories_handover.pdf`, …) and checks every reported number against the paper.

## 2. Re-run the experiments from scratch (GPU)

```bash
pip install -r requirements.txt
python run_experiments.py --list                 # show the 37 jobs without running them
python run_experiments.py --stage all --out runs # prepare -> screen -> steer -> seeds -> posthoc
python analyze.py --out runs --check             # compare your re-run with the paper
```

Stages can also be run one at a time (`--stage prepare|screen|steer|seeds|posthoc`); each depends on the previous one.
If a session is interrupted, run the same command again: finished jobs are skipped and unfinished jobs resume from
their last 1,000-step checkpoint.

| stage | jobs | what it runs | GPU-hours (T4) |
|---|---|---|---|
| `prepare` | – | download TinyStories, GPT-2 tokenisation, 8,192-token vocabulary, bigram table | CPU, ~10 min |
| `screen` | 8 | free hybrid + recurrent-only model, seed 0, at (ctx, *d_h*) ∈ {64/512, 32/512, 64/1536, 32/1536} | 7.7 |
| `steer` | 9 | never and late (λ = 0.1) arms from each seed-0 free checkpoint; λ = 0.3 at 64/512 | 2.9 |
| `seeds` | 12 | seeds 1–2 at 64/512 and 32/1536: free runs, then never / late arms | 6.9 |
| `posthoc` | 8 | matched post-hoc attenuation for every λ = 0.1 late arm | < 0.2 |
| **total** | 37 | | **≈ 17.6** (≈ 9–10 h wall-clock on 2× T4) |

Jobs are distributed over all visible GPUs. The paper used two Tesla T4s (fp16 mixed precision); on GPUs with bf16
support the code uses bf16 automatically, which can change results slightly.

## Protocol (details in Appendix R)

- **Data.** First 400,000 TinyStories stories, GPT-2 tokeniser, vocabulary restricted to the 8,192 most frequent tokens
  (token coverage 99.79%, 89.9M tokens); 2% held out. `run_experiments.py --stage prepare` checks these numbers.
- **Model.** Tied embeddings, four position-wise MLP blocks (*d* = 512), one GRU of width *d_h*, recurrent readout on
  *h_t*, 8-head retrieval read with query *h_t* over *h_{<t}* plus a learned sink, additive logits. 15.8M parameters
  at *d_h* = 512 and 25.7M at *d_h* = 1536.
- **Training.** AdamW (lr 3e-4, β = (0.9, 0.95), no weight decay), 500 warm-up steps then constant lr, clipping at 1,
  8,192 tokens per step. Free and recurrent-only models stop at a plateau (< 1.5% perplexity gain over three
  1k-step evaluations, minimum 6k steps) or at 20k steps.
- **Screen.** Viable if recurrent-only reaches ≥ 0.95 of the hybrid on perplexity and copy accuracy; load-bearing if
  deleting retrieval costs > 0.10 copy accuracy and multiplies perplexity by > 1.2.
- **Steering.** From each free checkpoint, *never* (λ = 0) and *late* (λ = 0.1) arms continue for 6k steps on the
  same data stream. The price is the ℓ2 norm of the retrieval logits divided by √V.
- **Metrics.** Deletion ratio *r* = ppl(retrieval deleted) / ppl; handover fraction
  *h* = 1 − log *r*_late / log *r*_never; *h*_copy and *h*_hard apply the same normalisation to the deletion cost in
  copy and hard-copy accuracy (hard copies: copy positions where a train-set bigram predictor is wrong).
  Complete handover requires *r* < 1.05, copy deletion cost < 0.01 and perplexity within 3% of the never arm.

## Expected results

| ctx / *d_h* | viability ppl / copy | seeds | ppl cost | *r*: never → late | *h* | *h*_hard | post-hoc ppl cost |
|---|---|---|---|---|---|---|---|
| 64 / 512 | 0.897 / 0.902 | 3 | +2.2% | 1.96 → 1.51 | 0.393 ± 0.006 | 0.075 ± 0.060 | +36.7% |
| 32 / 512 | 0.932 / 0.900 | 1 | +1.6% | 1.68 → 1.35 | 0.415 | 0.069 | +27.7% |
| 64 / 1536 | 0.933 / 0.918 | 1 | +1.4% | 1.53 → 1.34 | 0.320 | 0.132 | +22.3% |
| 32 / 1536 | 0.958 / 0.931 | 3 | +1.1% | 1.42 → 1.24 | 0.393 ± 0.025 | 0.034 ± 0.051 | +18.8% |

Post-hoc cost is relative to the late arm at the same retrieval contribution share. With λ = 0.3 at 64/512 (seed 0),
*h* = 0.58 at +4.3% perplexity and *r* = 1.31.

## Reproducibility notes

- Runs are deterministic given the seed on the same hardware and software: repeating a run reproduced every logged value.
  Different GPUs or library versions can change results slightly; `analyze.py --check` reports differences against
  tolerances in `expected/paper_numbers.json`.
- The dataset is downloaded from the Hugging Face Hub without a pinned revision. If the corpus changes, the data check
  in the `prepare` stage prints a warning.
- `results/posthoc/` was exported from the paper run, where the scale factor β was not logged; `posthoc.py` records it
  on a re-run.
- The logs also contain a random-token repeat probe (`rep_acc`), which was uninformative (≈0 for every model) and is not
  reported.
